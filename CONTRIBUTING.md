# Contributing

Thanks for helping improve ThreatGenix.

## Before opening a pull request

1. Open or reference an issue for non-trivial changes.
2. Keep the change focused and avoid unrelated refactors.
3. Add regression tests for behavior changes.
4. Run the backend and frontend verification commands from the README.
5. Never commit credentials, customer data, or unauthorized scan targets.

Security boundary changes need tests that demonstrate the failure mode is
blocked. Live validation must remain disabled by default.
